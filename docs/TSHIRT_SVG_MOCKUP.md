# T-shirt SVG mockup template

> The other products (hoodie, tote bag, mug, box, notebook, business card, flyer, poster) use the same structure:
> - built by `scripts/build-product-mockups.mjs`, one front side each, 1200 × 900;
> - `#artwork-front` slot and `print-area-front` clip path in each `public/mockups/svg/<product>.svg`.

`public/mockups/svg/tshirt.svg` is MSLAB's own vector T-shirt mockup: a regular-fit crew-neck tee with a **front** and a **back** view and four printable areas. It replaced the test photo (since deleted) as the Studio's T-shirt placeholder. See §5 for how the website uses it.

- 1200 × 1200 viewBox, transparent background, ~53 KB.
- No external files, fonts, images or base64. No scripts.
- Built only with paths, gradients, clip paths, filters and one pattern. Opens in any modern browser and in vector editors.
- Generated by `scripts/build-tshirt-mockup.mjs` (`node scripts/build-tshirt-mockup.mjs`).
  - The SVG is readable and editable by hand.
  - Use the script when the geometry changes, so the seams, stitching and print areas stay aligned.

## 1. Structure

```
<svg id="mslab-tshirt" class="mslab-tee" data-view="front" data-color="white">
  <metadata id="mslab-mockup-meta">  JSON: print areas, presets, scale
  <defs>                             styles, shared shapes, clip paths, filters, gradients
  <g id="view-front">                front view (shown by default)
  <g id="view-back">                 back view  (data-view="back")
```

Layers inside each view, from bottom to top. In the back view, the same IDs carry a `back-` prefix.

| ID (front) | Content |
|---|---|
| `shadows` | Soft drop shadow and contact shadow under the garment |
| `garment-base` | The fabric colour: the only element that uses `--garment-color` (plus the collar and neck interior) |
| `printable-areas` | Artwork slots. **Customer artwork goes here**, under the lighting, so folds, texture and seams fall on the print |
| `fabric-shading` | Body volume, edge falloff, collar and armhole cast shadows, underarm depth, drag folds, body folds, hem ripples, hem thickness |
| `sleeves` | Sleeve cylinder shading, sleeve-cap fullness, wrinkles, cuff ridge and edge |
| `fabric-texture` | Cotton grain, yarn slub, knit structure (visible when zoomed in) |
| `seams` | Armhole seams (with a raised highlight), shoulder seams, side seams |
| `stitching` | Twin-needle hem and cuffs, collar topstitch (front), back neck coverstitch (back) |
| `neckline` | Neck interior with shoulder-to-shoulder tape, inside of the back collar, 1×1 rib front collar |
| `highlights` | Chest and lower-body light, shoulder light, fold highlights, rim light |
| `print-area-guides` | Dashed outlines of the print areas. Hidden unless `data-guides="on"` |

Shared shapes live in `<defs>`:
- `shape-garment`, `shape-body`, `shape-sleeve-viewer-left`, `shape-sleeve-viewer-right`;
- `shape-neck-interior`, `shape-front-collar`, `shape-back-collar-inside`, `shape-back-collar-outside`;
- matching `clip-*` clip paths.

All shading is black or white at low opacity, never a tinted colour. Every fabric colour therefore keeps the same relief.

## 2. Printable areas

Each area is a `<clipPath id="print-area-…">` whose path is `print-area-…-shape`. Coordinates are in the 1200 × 1200 garment space.

**Left and right mean the wearer's left and right**, the POD convention. In the front view, the wearer's left sleeve is on the viewer's right.

| Area | View | Local size (w × h) | Rotation | Corners (TL, TR, BR, BL) | Bounding box (x, y, w, h) |
|---|---|---|---|---|---|
| `print-area-front` | front | 345 × 460 | 0° | (428,305) (773,305) (773,765) (428,765) | 428, 305, 345, 460 |
| `print-area-back` | back | 345 × 460 | 0° | (428,262) (773,262) (773,722) (428,722) | 428, 262, 345, 460 |
| `print-area-left-sleeve` | front | 115 × 138 | +22.64° | (940.5,275.3) (1046.7,319.6) (993.5,447) (887.4,402.7) | 887.4, 275.3, 159.3, 171.6 |
| `print-area-right-sleeve` | front | 115 × 138 | −22.64° | (153.3,319.6) (259.5,275.3) (312.6,402.7) (206.5,447) | 153.3, 275.3, 159.3, 171.6 |

The script checks the placement:
- the front and back areas lie inside the body panel (shoulder, armholes, collar and hem excluded);
- each sleeve area lies inside its sleeve, clear of the armhole seam and the cuff stitching.

The sleeve areas are rotated with the sleeve. The artwork stays upright relative to the sleeve.

**Scale.** The drawing uses 11.5 px = 1 cm (size M flat measurements: 52 cm chest, 72 cm length). `sizeMm` in the metadata follows from that scale: front and back 300 × 400 mm (a standard DTG platen), sleeves 100 × 120 mm. **These are illustrative, not MSLAB production specifications.** The real printable size still comes from `/admin/print-on-demand/studio/tshirt` (`printMm`), as `docs/STUDIO.md` §1 requires.

To read the areas programmatically:

```ts
const meta = JSON.parse(svg.getElementById("mslab-mockup-meta")!.textContent!);
meta.printAreas.front; // { view, clipPath, artworkGroup, width, height, sizeMm, rotationDeg, transform, corners, bbox }
```

Each slot also carries `data-print-area`, `data-width` and `data-height`.

## 3. Changing the colour

**Presets.** Set `data-color` on the root:
- `white`, `black`, `navy`, `red`, `royal-blue`, `grey`, `beige`, `forest-green`.

Each preset sets the fabric colour. It also tunes the strength of the shading, highlights and texture, so dark fabrics get a visible sheen and white fabrics are not over-lit:

```js
svg.setAttribute("data-color", "navy");
```

**Any colour.** Set the CSS custom properties on the root:

```js
svg.style.setProperty("--garment-color", "#7A1F3D");
// optional fine-tuning (0–1):
svg.style.setProperty("--shade-strength", "1");      // folds and volume
svg.style.setProperty("--highlight-strength", "0.6"); // ~0.35 on light fabrics, ~0.8–1 on dark ones
svg.style.setProperty("--texture-strength", "0.65");
svg.style.setProperty("--drop-shadow-strength", "1"); // 0 removes the shadow under the garment
```

Only the base fill changes. The shading, texture, seams and stitching are untouched black/white overlays, so the relief survives every colour.

The `fill` attributes in the file also hold a white fallback, for tools that ignore CSS variables.

**When the SVG is used as `<img src>` or a CSS background**, its styles cannot be changed from outside. Two options:
- inline it (fetch the text and insert it into the DOM), then use the attributes above;
- for a static file, replace the default value in the `<style>` block (`--garment-color:#F4F4F1`) before serving it.

## 4. Inserting customer artwork

Each area has an artwork group. Its local coordinate system runs from `0 0` to `width height`, top-left origin, y down. The group's `transform` already places, and for sleeves rotates, that box onto the garment.

| Area | Insert into |
|---|---|
| Front | `#artwork-front` (front view) |
| Back | `#artwork-back` (back view) |
| Wearer's left sleeve | `#artwork-left-sleeve` (front view) |
| Wearer's right sleeve | `#artwork-right-sleeve` (front view) |

```js
const NS = "http://www.w3.org/2000/svg";
function placeArtwork(svg, area, href, { x = 0, y = 0, width, height, rotate = 0 } = {}) {
  const g = svg.getElementById(`artwork-${area}`);
  const w = Number(g.dataset.localWidth), h = Number(g.dataset.localHeight);
  const img = document.createElementNS(NS, "image");
  img.setAttribute("href", href); // object URL or same-origin URL
  img.setAttribute("x", String(x));
  img.setAttribute("y", String(y));
  img.setAttribute("width", String(width ?? w));
  img.setAttribute("height", String(height ?? h));
  img.setAttribute("preserveAspectRatio", "xMidYMid meet");
  if (rotate) img.setAttribute("transform", `rotate(${rotate} ${x + (width ?? w) / 2} ${y + (height ?? h) / 2})`);
  g.replaceChildren(img);
}

```

What the template handles for you:
- Anything outside the area is clipped by the outer `slot-*` group, `clip-path="url(#print-area-…)"`, in garment coordinates.
- The slot applies `fx-print-on-fabric`, a very small displacement, so the print follows the knit.
- The fold shading, texture and highlights are drawn over the artwork: no extra blending is needed.

Optional: on white or light fabrics, `style="mix-blend-mode:multiply"` on the `<image>` makes ink look absorbed. Leave it off on dark fabrics, where prints are opaque (white underbase).

**Views and guides.**
- `data-view="front" | "back"` switches the view.
- `data-guides="on"` shows the print areas, for the editor.

**One instance per page.** The template uses fixed IDs. To show several copies inline, prefix the IDs (and their `url(#…)` / `href="#…"` references) per instance, or render each copy in its own `<img>` or iframe.

## 5. How the website uses it

- `node scripts/build-tshirt-mockup.mjs` writes the SVG and two modules. Never edit the `.generated.ts` files by hand.
  - `src/features/print-on-demand/tshirt-template.generated.ts`: the four Studio sides (`front`, `back`, `left_sleeve`, `right_sleeve`). Each side has its scene (front or back view), print area, rotation and editor crop. `placeholder-views.ts` exposes them as a `template` placeholder, and `placeholderSides()` makes the server action keep layers on all four sides.
  - `src/components/print-on-demand/garment/tshirt-layers.generated.ts`: each view split into an "under" document (shadow + fabric colour) and an "over" document (lighting, folds, texture, seams, collar).
- `garment/garment-template.ts` fills in the colour and turns each part into a cached SVG data URL.
  - The fabric lighting is tuned from the colour's lightness.
  - Any 6-digit hex is accepted; anything else falls back to white.
- The Studio stage (`studio/stage.tsx`) draws, in order:
  1. the under image;
  2. the customer's layers, clipped to the print area and rotated for the sleeves;
  3. the over image (`pointer-events: none`);
  4. the selection handles.
  The fabric filters are rasterized once per colour, not on every drag.
- The PNG export (`studio/export-mockup.ts`) draws the same three parts on a canvas, at 1600 px across the side's crop.
- Product cards and the homepage live proof use the front side, cropped to 4:3.

## 6. Checks performed

Run on Chromium (Playwright) after generation:
- valid standalone XML;
- 86 unique IDs, no duplicates, every `url(#…)` and `href="#…"` reference resolves;
- no external URL, raster image or base64;
- every print-area corner and edge midpoint lies inside the garment and inside the correct panel;
- `data-color`, a custom `--garment-color` and `data-view` take effect as expected;
- visual review of all 8 colours, front and back, with and without artwork, and a 3× zoom on the collar.
